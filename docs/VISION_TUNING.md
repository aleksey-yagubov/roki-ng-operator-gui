# Цвета и камера в существующем операторе

Панель встроена в `qml/Operator.qml`: меню «Панели → Цвета и камера», общие
dock-вкладки, Controller, Session, Control/lease. Это не отдельное приложение.
`scripts/preview_tuning.py` — изолированный тест рендера без docking-плагина.

## Порядок работы

1. Подключиться, получить управление и перейти в MANUAL стандартными кнопками.
2. Открыть «Цвета и камера», загрузить настройки. Defaults и диапазоны приходят
   с робота через params.keys/describe/get, не продублированы в GUI.
3. При необходимости остановить direct-gst. Явно запустить runtime-камеру
   кнопкой панели. Калибровочный старт использует with_imu=false;
   для локализации позже нужен новый синхронный захват с IMU.
4. В существующей панели «Видео» выбрать источник runtime и вывод
   appsink → QImage. Создание/приём потока идут через прежние Video/Receiver.
5. Выбрать цветовой класс, взять свежий кадр. Снимок фиксируется для сравнения
   маски при движении ползунков. Клик по левой картинке предлагает границы LAB
   по области 7×7 с регулируемым допуском. Предложение — только черновик.
6. Проверить маску и сохранить фильтр. Все изменённые границы уходят одной
   params.set, с проверкой исходных значений против перезаписи чужих правок.
7. Запустить детектор робота и запросить статус, либо включить его обновление.
   Результат содержит собственный frame_sequence, класс, области и возраст.
   Для другого класса остановить детектор и запустить с новым выбором.
8. На вкладке «Камера» выставить выдержку/gain/AE/AWB/WB и сохранить группу.
   Кнопки фиксации берут свежие метаданные на роботе, отключают соответствующую
   автоматику и сохраняют значения атомарно. Нет свежих данных — нет фиксации.

## Точность preview и применение

Правая картинка — CIELAB D65 маска декодированного, уменьшенного RGB-снимка,
считает только цветовой диапазон. Она не моделирует отсев компонентов по
площади. Кодек, масштабирование и округление OpenCV могут менять граничные
пиксели по сравнению с BGR-кадром робота. Это подписано в интерфейсе.
Результат роботного детектора показывается отдельно: нельзя накладывать его
рамки на видео без подтверждённого общего номера кадра. Локальный image_serial
не выдаётся за UnicamSequence. Direct-gst можно исследовать как снимок, но
camera.* к нему не применяются; источник явно отображается.

Черновики не влияют на робота до сохранения. «Стандартный фильтр/камера» меняет
черновик; «Отменить» возвращает прочитанные значения. Ошибка записи оставляет
черновик. После потери связи очищаются снимок и параметры предыдущей сессии.
Периодический запрос статуса — только по флажку, раз в секунду и только пока
панель видна. Открытие панели не запускает камеру, видео или детектор.

## Проверки

13 целевых GUI-тестов: LAB-эталоны, пипетка/черновик, stale/disconnect,
текст ошибки Session, runtime video без sensor override, редактирование карты.
Qt Quick offscreen: панель загружена, клик по изображению изменил шесть границ,
вкладка камеры открылась; сохранены изображения обеих вкладок. Проверка выполнена
отдельно от Linux docking-плагина. Сквозной прогон на роботе/в Linux GUI ещё нужен.

`scripts/check_tuning_contract.py` проверяет настоящие модели GUI и dispatcher
roki-ng с сериализацией каждого запроса/ответа: 118 запросов, максимальный пакет
587/1200 байт. Прочитаны реальные схемы и сохранены LAB, камера и метка поля.
Аппаратные worker-ы заменены mock; сеть, авторизация lease и настоящая камера
этим тестом не подтверждаются. Локальная проверка runtime: 62 целевых теста
камеры, параметров и локализации проходят.

Мастер шахматной калибровки и импорт npy этой панелью пока не реализованы.
