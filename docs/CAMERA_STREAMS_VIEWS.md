# Камера, стримы и просмотры

Источник протокола: `roki-ng/docs/GUI_CAMERA_VIDEOSTREAM_HANDOFF.md` и
`CAMERA_VIDEOSTREAM_PROTOCOL.md`. GUI и runtime обновляются вместе.
Конверт MessagePack без `v`, hello без `versions`, максимум 1400 байт.

## Три независимых слоя

**Камера** управляет camera-worker и ISP через `camera.*`, отдельно от передачи.
Запуск камеры требует IMU. Остановка требует подтверждения, поскольку затрагивает
зависимые вычисления. Временное применение ISP и сохранение профиля разделены.

**Стримы** показывает именованные видеовыходы воркеров из `videostream.list`.
Каталог загружается страницами по одному элементу. Имена не зашиты в GUI:
сейчас это `stream`, `camera`, `localisation`. Недоступные выходы остаются в списке
с причиной. `stream` сам захватывает камеру GStreamer без IMU; остальные требуют
работающего производителя. Подписка не запускает детекцию или локализацию.
Нет пользовательских определений, UUID потоков, create/destroy и выбора кодека.
Передача только H.264/PT96/90000; размеры объявляет производитель, без resize GUI.

**Просмотр** — локальная docking-панель QImage. Несколько панелей одного выхода
делят один приёмник, декодер и последний кадр. Селектор показывает только уже
принимаемые выходы. Перенос/закрытие/удаление панели не посылает команд роботу.
Можно создать любое число просмотров через меню панелей или «Ещё просмотр».

## Порядок работы

1. Нажать «Запросить видеовыходы» и выбрать выход.
2. При необходимости изменить поля и нажать «Применить» возле каждого поля.
   Поля строятся из `controls`, значения из `settings`: fixed всегда read-only,
   live доступно владельцу при работе, остальные меняются только до запуска.
   Изменения общие для всех получателей; после update запрашивается status.
3. Нажать «Смотреть». Приёмник сначала связывает свободный UDP-порт и запускает
   пайплайн, затем отправляется subscribe с именем и фактическим портом.
   Остановленный выход может запускать только владелец управления;
   к работающему подключается и наблюдатель. Настройки в subscribe не передаются:
   они применяются явно через update, без перезаписи настроек чужой передачи.
4. После подтверждения открывается существующий просмотр этого выхода либо новый.
   Дополнительные просмотры не создают подписки. Декодер и ручной UDP-порт
   находятся в дополнительных настройках; по умолчанию порт выбирает ОС.
5. «Отключиться» отправляет unsubscribe только для своей сессии. Последняя
   подписка ушла — передача прекращается. Автономная игра не останавливается.
   «Остановить для всех» требует управления и подтверждения при других зрителях.

## Состояния и ошибки

Подключение оператора не захватывает управление и не запрашивает видеокаталоги.
Доступность протокола проверяется по `system.operations`, не по номеру версии.
После первого явного запроса каталог и статусы обновляются с ограниченной частотой.
Статус дополняет описание: title и controls сохраняются из каталога.
`producer.requested/publishing` показаны отдельно от состояния кодера.

Модели селекторов уведомляют QML только при изменении содержимого.
FPS/RTT не пересоздают селекторы и формы. Декодирование, импорт/инициализация
GStreamer, копирование кадра и остановка пайплайна работают в отдельном Qt-потоке.
Qt получает только последний кадр и не накапливает очередь изображений.

При неизвестном исходе subscribe перечитывается `status.subscribed`, без нового
запуска. Конфликт настроек показывается с обновлением подтверждённого состояния;
GUI не останавливает чужую передачу. Ошибка приёмника снимает свою подписку.
Смена run_id/SSRC, остановка или потеря связи очищают старые кадры.
После reconnect/смены boot_id каталог обновляется, если его уже запрашивали,
но приём и подписки не восстанавливаются автоматически. Раскладка сохраняет
только локальные панели, не подписки и не параметры запуска.

## Проверки

- `tests/test_video.py`: имена, пагинация, наблюдатель, controls, подписки,
  общие приёмники, смена запуска, неопределённый исход и локальные просмотры.
- `scripts/test_operator_gui.py`: клики, динамические поля, выбор и открытие просмотра.
- `scripts/test_video_gui.py`: реальный H.264 RTP по loopback, VA/программный декодер,
  геометрия 800×650, измеренный FPS, перенос QImage между окнами и перезапуск.
- `scripts/check_videostream_compat.py`: отдельный локальный `roki-ng --simulate`.

OSD и точная LAB-калибровка по lossless-кадрам не входят в эту задачу.
Windows и реальные аппаратные camera/stream-worker требуют отдельной проверки.
