# Камера, стримы и просмотры

GUI следует camera.* / videostream.* из
roki-ng/docs/GUI_CAMERA_VIDEOSTREAM_HANDOFF.md. Отдельного wire-протокола нет.
Обычные MessagePack-датаграммы ограничены 1400 байтами.

## Три независимых слоя

**Камера** управляет camera-worker: статус, запуск, остановка и ISP-контролы.
Геометрия runtime фиксирована контрактом: 1600×1300 RAW10 → 800×650 BGR.
Оператор задаёт период кадра; захват требует IMU. Остановка требует подтверждения,
поскольку завершает зависимые детекторы, локализацию и их видеопередачи.
Применение ISP и Freeze временные, сохранение в профиль отдельное.

**Стримы** управляет stream-worker и локальными приёмниками.
Источники берутся из videostream.sources с пагинацией, а не из локального enum.
Только direct-gst показывает поля режима сенсора: это захват stream-worker,
не camera-worker. Другие источники используют уже работающих производителей.
Недоступность источника показывается вместе с причиной; определение можно
создать заранее, но возможность запуска решает робот.

**Просмотр** является исключительно локальной docking-панелью QImage.
Добавляется через меню панелей или «+ Просмотр». Селектор содержит только
активные локальные приёмники. Панель не вызывает create/start/attach/detach.
Число просмотров не ограничено фиксированными двумя окнами.

## Порядок работы

1. Запросить источники и определения передач в «Стримах».
2. Выбрать источник, размеры выхода, кодек и частоту; создать определение.
   Для runtime/localisation сначала отдельно запустить соответствующий producer.
3. Выбрать определение. Указать свободный UDP-порт и декодер ПК.
4. «Запустить и принимать» требует управления. «Подключить мой приёмник»
   позволяет наблюдателю подключиться к уже работающей передаче без lease.
   В обоих случаях локальный пайплайн готов до отправки команды роботу.
5. Создать просмотры и выбрать в каждом уже принимаемый стрим.
6. Для прекращения только собственного приёма нажать «Отключить мой приёмник».
   «Остановить для всех» и «Удалить определение» требуют управления.

Каждому stream_id соответствует один Receiver с отдельным рабочим Qt-потоком.
Декодер и сеть не зависят от количества, видимости или положения просмотров.
Кадры передаются через общий QImage-провайдер; удерживается только последний.
LAB-тюнер также читает этот общий приёмник. В локализации собственного
видеоплеера больше нет: её источник выбирается в том же каталоге.

## Состояния и ошибки

Каталоги запрашиваются явно. После первого запроса обновляется список передач;
статусы активных приёмников читаются с ограниченной частотой, без накопления
повторных запросов. Разные приёмники не могут занять один UDP-порт.
Потеря lease не выключает уже работающий приём.

Изменение run_id/SSRC, остановка роботом или ошибка декодера очищают кадр.
Автоматического повторного запуска нет. Неопределённый исход create блокирует
повторное создание до явной проверки списка и подтверждения оператором.
Ошибки показываются в «Стримах» и журнале.

Закрытие просмотра только скрывает панель; «Удалить просмотр» удаляет её
из локальной раскладки. Сохранение раскладки записывает layout.json и
video-views.json в каталог настроек. Восстановленные панели пусты:
подписки, старые stream_id и приёмники между сессиями не восстанавливаются.
Старая раскладка может содержать удалённую фиксированную панель изображения:
откройте новые панели через меню и сохраните раскладку заново.

## Проверки

- tests/test_video.py: разделение create/start, наблюдатель без lease,
  общие приёмники, уникальные порты, смена run_id, ошибки и локальные просмотры.
- tests/test_camera.py: камера без запуска передач, controls, apply/save/freeze.
- scripts/test_operator_gui.py: клики и раскладка обычного интерфейса.
- scripts/test_video_gui.py: реальный RTP по loopback, аппаратные/программные
  H.264/JPEG-декодеры, несколько просмотров одного потока, перенос между окнами.
- scripts/check_videostream_compat.py: отдельный локальный supervisor --simulate.

OSD и синхронизация результата детектора с видеокадром в этот этап не входят.
Windows и реальные аппаратные camera/stream-worker требуют отдельной проверки.
