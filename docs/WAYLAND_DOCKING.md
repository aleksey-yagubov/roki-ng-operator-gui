# Стыковка панелей на Wayland

Проверено на KDDockWidgets 2.4.1, Qt 6.11.2, labwc, 2026-09-26.
Исправление: `scripts/patches/kddw-wayland-drop.patch`.
Сборочный скрипт применяет его идемпотентно. Системные библиотеки не меняются.

## Две ошибки Qt Quick frontend

1. Нативный `QtQuick::DropArea` не выставлял `ItemAcceptsDrops`.
   Для FloatingWindow есть QML DropArea-обёртка, для MainWindow её нет.
   Поэтому drag запускался, но главное окно не получало события drop target
   и не показывало подсказки. Добавлен флаг приёма событий в нативной области.
2. `StateDraggingWayland::handleDragMove` обновлял подсказки, но не принимал
   событие. Глобальный фильтр поглощает его: обычный QML handler уже не вызывается.
   Wayland получал отказ, поэтому отпускание отменяло drag. Теперь enter/move
   явно принимаются с MoveAction. Сам drop по-прежнему проверяется библиотекой.

После первого исправления пользователь подтвердил появление подсказок.
После второго подтвердил реальное перемещение внутри главного окна.
Также подтверждено обратное встраивание плавающей панели перетаскиванием.
Это отдельная проверка, не прежний тест кнопки float.

## Штатные ограничения

Согласно документации upstream `docs/book/src/qpa-wayland.md`:

- Внешний системный заголовок плавающего окна перемещает окно, но не стыкует.
- Внутренний заголовок панели запускает drag-and-dock.
- Вынос в новое окно выполняется кнопкой float или двойным щелчком по заголовку
  / вкладке. Отпускание drag вне подходящей области не создаёт новое окно.
- Восстановление координат плавающих окон ограничено Wayland.

Не подменяем это собственной эмуляцией X11-перемещения окон.
Перенос живого QImage-видео проверяется отдельно в scripts/test_video_gui.py.
