# ROKI NG Operator GUI

Отдельный проект программы оператора. Роботная часть остаётся в соседнем
`../roki-ng`. Приложение наблюдения и ручного управления на PySide6,
Qt Quick и KDDockWidgets, с отдельным сетевым потоком UDP MessagePack.

## Основное приложение

В репозитории уже есть готовый KDDockWidgets для **Linux x86_64 / Qt 6.11.2**.
На совместимой системе собирать его не нужно: установите PySide6 6.11.2 и
msgpack, затем запускайте из корня проекта. GStreamer и PyGObject нужны для видео.
Проверялась установка с системными PySide6/Qt; совместимость с другой копией Qt
из pip не гарантируется. [Состав и ограничения бинарников](native/README.md).

```sh
python roki_operator.py --robot 172.30.0.1
```

Адрес только подставляется в поле. Подключение начинается по кнопке и включает
сессию, heartbeat и журнал, но **не захватывает управление, не запускает камеру
и не загружает каталоги автоматически**. Слоты, тесты, состояние и параметры
запрашиваются отдельными кнопками. В верхней панели нажмите «Получить управление»,
затем в панели управления «Ручной режим». После этого доступны движения,
слоты и тесты. Для записи параметров достаточно владеть управлением.
«Ручной режим» работает как переключатель: выключение отправляет `mode.set IDLE`,
останавливая очередь тела без отдачи управления и без завершения процессов.
Команды управления/остановки выделены справа в однострочной верхней панели.
Статус связи, имя робота и режим расположены посередине; при нехватке места
текст сокращается, полная строка доступна во всплывающей подсказке.
«Слоты» и «Тесты» — независимые docking-панели: доступны отдельно в меню
«Панели», могут одновременно отображаться и выноситься в разные окна.
Старая сохранённая раскладка с объединённой панелью каталогов может потребовать
повторного открытия этих панелей через меню и сохранения обновлённой раскладки.
Список «Присед» задаёт `crouch`: не оставаться (`off`, по умолчанию), обычный
(`on`) или центрированный (`centered`). Режим передаётся в ходьбу, включая
нулевые команды остановки, прыжки/повороты, вставание и splits. Явная кнопка
Crouch всегда присаживает: при off выбирается обычный присед.
«Удерживать курс по IMU тела» передаёт `heading_hold` в ходьбу; по умолчанию
выключено. Это не стабилизация равновесия и не использование IMU головы.
В Actions добавлены «Встать после падения», Splits и «Шпагат». После splits
возврат только по команде Crouch/Stand/Base; автоматического повтора вставания нет.
Новые движения требуют физической проверки на стойке. Старые поля
`hold_crouch` и `auto_prepare` больше не отправляются.
В блоке Head слайдеры редактируют черновик, который отправляется кнопкой Apply.
Стрелки работают от последней подтверждённой цели, не от черновика; Pan 0 и
Tilt 0 меняют только указанную ось. Turn steps задаёт шаг в ticks за нажатие.
В ручном режиме GUI запрашивает `motion.state` дважды в секунду, чтобы обновлять
голову после Field/Base и других движений. Это заданная цель, не измеренное
положение серв. Пока цель неизвестна, относительные повороты недоступны.
В каталоге слотов/тестов также есть кнопка перехода в ручной режим и объяснение,
почему запуск сейчас заблокирован. В параметрах доступны группы по префиксу
ключа и поиск; нижний редактор занимает только нужную ему высоту.
Панель «Источники данных» позволяет запросить список, прочитать снимок или
подписаться на обновления состояния без захвата управления. Выбор источника
сам по себе ничего не запускает; исходные ответы скрыты под галочкой.
После подключения автоматически включается только телеметрия аккумулятора
`body.power` с частотой 1 Гц (помимо журнала). Управление, камера и IMU для неё
не нужны. Строка состояния показывает напряжение в вольтах, не процент заряда;
симуляция помечается явно. Возраст учитывает время на роботе и после получения
на ПК: через 3 секунды вместо напряжения появляется «данные устарели».
При отсутствии/ошибке чтения отображается «нет данных», не 0 В. Во всплывающей
подсказке доступны ADC, возраст и ошибка; полный снимок и отключение подписки
доступны в «Источниках данных». При новом подключении подписка включается снова.
Камера, передачи и просмотры разделены:
- «Камера» управляет camera-worker и ISP, не запускает передачу.
- «Стримы» запрашивает объявленные воркерами видеовыходы. «Смотреть» подключает
  приёмник и открывает просмотр, «Отключиться» снимает только свою подписку.
  Поля настроек берутся из каталога робота; только H.264, без создания определений.
- «Панели → Добавить просмотр видео» создаёт произвольное количество docking-панелей.
  Каждая выбирает уже принимаемый стрим. Два просмотра одного стрима используют
  один приёмник и декодер. Закрытие/удаление просмотра не останавливает передачу.

Декодер выбирается отдельно для каждого приёмника; вывод всегда appsink → QImage.
Каталоги, запуск камеры и подключение приёмника требуют
отдельного действия. Восстановление раскладки не восстанавливает сетевые подписки.
В панели зрения доступны LAB-проверка выбранного цвета и отдельный запуск
игрового детектора мяча без движений. Источник `detection` в «Стримах» показывает
маски с робота, рамки и причины отбраковки; его видео также видно в панели зрения.
Пипетка работает по исходному `camera`, её preview приблизительный; роботные
маски используют сохранённые параметры. Для мяча нужны синхронная IMU и профиль
оптики. Инструкция: [настройка зрения](../roki-ng/docs/VISION_TUNING.md).

LAB-тюнер выбирает один из активных приёмников, локализация больше не содержит
особого видеоплеера. OSD отложен; GStreamer загружается только при запросе видео.
Подробнее: [Архитектура камеры, стримов и просмотров](docs/CAMERA_STREAMS_VIEWS.md)
и [Приём видео](docs/VIDEO_RECEIVER.md).

Журнал является единым текстовым полем: можно выделять несколько записей
и копировать через Ctrl+C. Пока есть выделение, показанный текст не меняется,
но новые записи продолжают приниматься; после снятия выделения просмотр обновляется.
«Копировать журнал» копирует все строки текущего фильтра, а не только видимые
на экране. Галочка клавиатуры сохраняет выбор в течение работы приложения:
потеря фокуса, скрытие панели и остановка отпускают кнопки, но не снимают её.
После возврата в окно движение само не возобновляется. Без управления и режима
MANUAL клавиатурные команды не обрабатываются; Ctrl/Alt/Meta-сочетания остаются
обычными сочетаниями приложения.

Панели можно перетаскивать, выносить в окна, закрывать и открывать через меню
«Панели». Кнопки сохранения/восстановления работают с `layout.json` в каталоге
конфигурации Qt для `ROKI/roki-ng-operator`. Для изолированной проверки:
`--config-dir artifacts/my-layout`.
Для Wayland включён локальный фикс приёма drop-событий:
[подробности и ограничения](docs/WAYLAND_DOCKING.md). За системный заголовок
плавающее окно только перемещается; для стыковки нужен внутренний заголовок.
Вынос наружу: кнопка float или двойной щелчок.

Нужны PySide6, msgpack и локальный QML-модуль KDDockWidgets из `native/qml`.
Готовый модуль включён в репозиторий, пересборка для другой среды описана ниже.
Без видео приложение не требует GStreamer.

```sh
python -m unittest discover -s tests -v
python scripts/test_operator_gui.py
python scripts/check_runtime_compat.py --runtime-dir ../roki-ng
python scripts/check_runtime_compat.py --exercise-controls
```

Последний тест запускает только локальный `--simulate`, не настоящий робот.
Подробности, ограничения и следующие этапы:
[Основа приложения](docs/OPERATOR_FOUNDATION.md).

Docking проверяется на настоящем интерфейсе через `scripts/test_operator_gui.py`:
вынос и возврат панелей, независимые вкладки, сохранение и восстановление раскладки.
Тест открывает окна и сам завершается. Результаты и снимки сохраняются в `artifacts/`.

## Проверка видео

Для неё нужны PyGObject (`gi`), типы GStreamer для GI, элементы RTP,
парсер H.264, выбранные декодеры, `videoconvert` и `appsink`.
Для тестового отправщика также нужны `videotestsrc` и `openh264enc`.
`pip install PySide6` не устанавливает GI и плагины GStreamer.

```sh
python scripts/test_video_gui.py
```

Проверяется H.264 с аппаратным и программным декодерами, вывод в QImage,
FPS, остановка/повторный запуск и перенос живой видеопанели между окнами.
Тест работает только через loopback, без подключения к роботу.
Подробнее: [приём видео](docs/VIDEO_RECEIVER.md).

Отдельно выполнен [тест удержания VA/DMA-BUF/GL кадров](docs/GPU_BUFFER_RETENTION.md):
`python scripts/probe_gpu_retention.py`. Это проверка кеша ссылок на GPU-буферы,
без Qt и без подключения к роботу.

## Локальная сборка зависимости

Используется KDDockWidgets v2.4.1, commit
`c1d28d25ef5ba077915bcb2b6fa9e14df2a361f8`.

```sh
DOWNLOAD_PROXY=socks5h://127.0.0.1:1080 bash scripts/build_kddockwidgets.sh
```

Прокси нужен только для скачивания, глобальные настройки Git не меняются.
Сборка по умолчанию использует все доступные CPU; можно задать `JOBS=4`.
Нужны CMake, Ninja, C++17-компилятор, Git, patchelf и dev/private-заголовки
Qt Quick/Quick Controls того же Qt, который использует PySide6.

- `.deps/src/` содержит скачанные исходники.
- `.deps/build/` содержит сборку.
- `native/qml/` содержит готовый локальный QML-модуль и его библиотеки.
- `native/licenses/` содержит лицензии зависимости.

Сборка не требует root и ничего не устанавливает в `/usr`. Python-биндинги
KDDockWidgets не собираются: PySide6 загружает нативный QML-плагин.
После переноса файлов зависимости ищутся рядом с плагином через `$ORIGIN`.

## Раздача папкой

Для запуска нужны `roki_operator.py`, каталоги `operator_gui/`, `qml/` и `native/`,
совместимые PySide6/Qt и зависимости из `requirements.txt`.
Для видео дополнительно нужны GStreamer и GI.
Каталог `.deps/` пользователю не нужен. Исполняемая часть `native/` занимает около
4,2 МиБ в текущей Linux x86-64 сборке; это не размер всей среды исполнения.
Отдельно приложен архив исходников зависимости в `native/sources/`, для запуска
он не нужен. Полные каталоги сборки в Git не включаются.

Переносимость проверена только между каталогами на одном ноутбуке.
Этот бинарник не объявляется совместимым со всеми Linux-дистрибутивами,
другими версиями Qt или Windows. Нативную часть под Windows ещё не собирали.
`requirements.txt` фиксирует проверенную версию PySide6, но не заменяет
согласование нативных Qt/GStreamer-плагинов. Не смешивать без проверки
системный Qt и другую копию Qt из pip-wheel.

KDDockWidgets распространяется под GPL-2.0-only OR GPL-3.0-only либо коммерческой
лицензией. Тексты лицензий, исходники зависимости и применённый патч включены
в репозиторий; ссылки приведены в `native/README.md`. Эти лицензии относятся
к зависимости и не назначают автоматически лицензию собственному коду GUI.

## Границы текущего этапа

Работают ручные движения, запуск/остановка тестов, слоты и редактор параметров.
Раскладка Walk / Actions / Head перенесена из старого ручного клиента;
подключение, журнал и каталоги остаются отдельными панелями. Hard L/R пока
неактивны: новый runtime не предоставляет аппаратный удар.
Панель игры описана ниже. Сервис сервоприводов и OSD будут добавляться отдельно.
Порядок согласования будущих схем с роботной частью:
[Передача контекста между агентами](docs/COLLABORATION_HANDOFF.md).


## Автономная игра

Откройте «Панели → Игра». Подключение само по себе не запускает игру.
«Запросить статус» доступен без управления. Для запуска получите управление,
включите ручной режим и выберите целую задержку 0–30 секунд.
Выберите FIRA_penalty_Goalkeeper или forward; для forward — center/left/right.
«Запустить игру» включает физические движения. Observe only и ручного флага
готовности геометрии нет. Стартовый манёвр немедленного center настраивается
обычным параметром game.forward.kick_off_ride и применяется на следующий запуск.
Задержанный center и боковые вводы не используют манёвр.
Игровая логика использует исходную FIRA-таблицу, рассчитанные серии ходьбы,
подход/обход и доводку перед ударом. Forward завершает игру после 6 минут.
Наблюдение выполняется в base_stand; удержание crouch — только ручной режим.
Высота камеры, диаметр мяча и расстояния доводки редактируются через обычные
params (game.camera_height_m, game.ball_diameter_m, game.kick_*_mm).

«Пауза» запрещает следующие действия; «Продолжить» возобновляет подготовку
и поиск. «Pick up» запрашивает перенос: дождитесь отдельного сообщения о готовности.
Если робот лежит, установите его вертикально и нажмите «Робот установлен
вертикально». До подтверждения вставание/стойка автоматически не запускаются.
После готовности выберите новую роль и ввод и нажмите «Повторный ввод».

Во время игры режим меняется на GAME, ручные движения блокируются.
«Получать данные игры» запрашивает `data.subscribe` для `game.state` с частотой
2 Гц. «Получать данные позиции» подписывает на `localisation.state` с той же
частотой. Панели игры, локализации и источников данных используют общие подписки:
переключение панелей их не отключает, явное отключение действует для всех просмотров.
При подключении эти подписки не запрашиваются. Они не запускают игру, локализацию,
камеру или видео и не требуют управления. Разовые кнопки статуса не включают опрос
по таймеру. После разрыва связи подписки запрашиваются оператором заново.
«Остановить игру» доступна владельцу управления
в GAME и прерывает ожидающую команду. Панель показывает причины остановки,
ошибки, фазу, восстановление связи/вставание, решение, мяч и игровую одометрию.
Пройденный путь оценивается по подтверждённым калиброванным участкам;
это не гарантия физической точности при проскальзывании. Панель показывает
последнюю визуальную поправку. Локализатор выдаёт valid по качеству и свежести;
во время игры три согласованных кадра в стойке корректируют одометрию.
Ручные start/stop локализатора во время игры недоступны, просмотр остаётся.
Ни valid=true, ни прохождение автотестов не подтверждают полевую точность.

Проверки `tests/test_game.py` используют только локальный FakeRobot;
`scripts/test_game_gui.py` проверяет QML без взаимодействия с экраном.
Они подтверждают контракт команд, владение, остановку, ошибки и элементы
панели, но не калибровку камеры, реальную траекторию и качество вратаря.
